#What the installers ship:  the one list OpcHubSetup.nsi (through files.ps1, as it compiles), build-setup.ps1 (what must
#exist, what -Sign signs) and linux/build-deb.sh read.  Each script keeps its packaging's own files:  the Web UI, the units
#and services, env, nginx-opchub.conf, web.config, the Visual C++ runtime, Jde.CheckCpu.exe and the docs.
#
#A file a line, its columns separated by spaces, and a # starts a comment:
#  section  hub - always installed;  opcserver - the OPC UA Server:  an optional component on Windows, always in the .deb, and
#           dropped by the tarball's install.sh without --opcserver
#  ships    all, windows, linux, or user - a current-user overlay:  the Windows installer's in either mode, and the Linux
#           tarball's but not the .deb's, whose units run args/install, where the machine's administrator decides the address
#  to       program - the section's program dir:  <program dir>\OpcHub or \OpcServer, /opt/jde-cpp/opchub or /opcserver
#           config/<dir> - under the settings mirror:  C:\ProgramData\Jde-Cpp\config, /etc/jde-cpp
#           data/<dir> - under the data root:  C:\ProgramData\Jde-Cpp, /var/lib/Jde-Cpp
#           A trailing ! marks a dir the installer owns:  recreated before the first file the list puts in it, so a file an
#           older version shipped cannot linger.  The .deb's dpkg and the tarball's install.sh replace those dirs themselves.
#  from     a path in the repo, build:<path> in the release build tree, or nodesets:<path> in the UA-Nodeset clone;  a *
#           matches as in a shell
#  as       the installed name, when it is not the source's
