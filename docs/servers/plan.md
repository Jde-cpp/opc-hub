# Servers implementation plan - 2026-10-19

A plan for [`spec.md`](spec.md) (2026-10-19), whose open questions were ruled as recommended the same day. It has the shape of the historian's plan ([`libs/historian/docs/plan.md`](../../libs/historian/docs/plan.md)): prerequisites that are each useful alone, then the spec's pieces in dependency order, each phase a PR or two with its own tests, and three milestones that merge end to end. Status is tracked on GitHub: [#377] is the parent, each phase below names its issue, whose body is the plan's text at filing and is refreshed from here after a fold, and the milestones are [I](https://github.com/Jde-cpp/opc-hub/milestone/5), [II](https://github.com/Jde-cpp/opc-hub/milestone/6) and [III](https://github.com/Jde-cpp/opc-hub/milestone/7).

Line numbers cite opc-hub2 at `04ef20c9`, as the spec does. Refs re-anchored on 2026-10-23, the UA server library's move among them, cite branch `servers-1a-ua-server-library`.

Three things the spec's piece table does not say:

- **The gateway refactor lands first.** [`gateway-refactor.md`](../../../reviews/gateway-refactor.md)'s A1 to A29, B1 and C are committed on `gateway-refactor` (`48d4d675`), with `UAClient` edits staged and no PR on 2026-10-19. It reshapes what Phases 3 and 5 build on: `HistGroupHost`, `HistHost` (the `HistWork` await gone, its hooks returning `AnyVoidTask`), `WriteAwait` on the new `UAAwait` base, and the test fixtures `ClientFixture`, `HistGroupFixture` and `HistReadFixture`. Phase 1 touches none of it and can start now; the rest branch from main after it merges, and the spec's cites under *Live values*, *Writes* and *History* are refreshed then.
- **Piece 3 is two phases**, the address space and the live values, since each is a PR of its own size and the first is useful without the second: a restart serves the folders and attributes before any source is up, which is what *Open questions* #7 asks for.
- **The attribute columns are a prerequisite, not part of the mirror.** They are a change to the collector and the tables, which the mirror only reads, and they are useful on the Members tab before any endpoint exists.

## Phase 5 - write-through (piece 5)

The value source's `write` ([#386]) answers `Good_CompletesAsynchronously`, posts to the executor, and the task runs a `WriteAwait` on the collector's client ([`UAClient.h:42`](../../apps/OpcGateway/src/UAClient.h#L42) with the collector credential) and answers with `UA_Server_setAsyncWriteResult` and the source's status; `asyncOperationTimeout` is `writeTimeout`. The gate: Update on the group's row, enforced, and the source's Write bit; a write on an unenforced resource is refused, as #237 ruled for edits. The audit line at Information: the hub user, the node and the source's answer. One forward at a time per node, in order; coalescing is the spec's *Later*. The remap pass runs the other way on the written value, and the spec's four edges hold: a Write with an IndexRange refused `Bad_WriteNotSupported`, a client's status and timestamps forwarded as given, a late answer logged and dropped, since `UA_Server_setAsyncWriteResult` then answers `Bad_NotFound`, and `maxAsyncOperationQueueSize` from `limits`. Tests: write through a served node and read it back at the OpcServer, and a structure written through; a refused write on an unenforced row; a write while the connection is down answers the client's status, not Good.

## Risks

- **The library shaped by its first host.** No gateway implementation exists before Phase 2, so 1b's interfaces are reviewed against both hosts on paper; a change 3a or 4 needs goes in that phase's PR, as the historian's did.
- **The service lock.** The value source's reads and the history reads run under it on the endpoint's thread; the mirror's lock is held for a copy, and on the strand side for a store. Log how long the callbacks held it at shutdown, as `UAHistory::Reads` does, and soak the hub with the emulator before milestone I closes. The lock order of the spec's *Threading* holds throughout: the mirror's lock innermost, no `UA_Server_*` call under a host's lock, no host lock or `Authorize::Test` under the service lock (review #5).
- **Threading on Windows.** `UA_Server_*` from the collector's strands and the executor relies on `UA_MULTITHREADING` at 100; both Linux installs have it, and the Windows preset is unverified. Check its `config.h` before Phase 2, which already writes `_Connection` from the executor.
- **The in-flight refactor.** Phases 3 and 5 branch after it merges; starting on its branch would merge twice.
- **Spec drift.** A PR that changes behaviour changes `spec.md` with it, and the open questions' rulings are folded as they come.
