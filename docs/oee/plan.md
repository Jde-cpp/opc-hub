# OEE implementation plan - 2026-10-20

A plan for [`spec.md`](spec.md) (2026-10-19), whose fifteen open questions were ruled 2026-10-20 and whose review ([`oee-spec-review.md`](../../../reviews/oee-spec-review.md), 16 findings) was folded the same day. It has the shape of the calendar plan ([`../calendar/plan.md`](../calendar/plan.md)) and the servers plan ([`../servers/plan.md`](../servers/plan.md)): the spec's pieces in dependency order, each phase a PR or two with its own tests, and three milestones that merge end to end. Status is tracked on GitHub: [#398] is the parent, each phase below names its issue, whose body is the plan's text at filing and is refreshed from here after a fold, as the servers plan's are, and the milestones are [I](https://github.com/Jde-cpp/opc-hub/milestone/11), [II](https://github.com/Jde-cpp/opc-hub/milestone/12) and [III](https://github.com/Jde-cpp/opc-hub/milestone/13).

Line numbers cite opc-hub2 at `4bf17829`, main with the gateway refactor merged, as the spec does. Refs re-anchored on 2026-10-23, the UA server library's move among them, cite branch `servers-1a-ua-server-library`.

Five things the spec's piece table does not say:

- **The calendar comes first.** Phase 1's formulas run over `Jde.CalendarLib`'s `Calendar` (calendar plan Phase 1), the host holds the gateway's calendar client (its Phase 3), and the machine form's calendar picker reads `calendars` through the AppServer's GraphQL (its Phase 2). So Phase 2 here starts after the calendar's Milestone II, and nothing waits on the calendar's web phases; Phase 1 can start as soon as the calendar library merges.
- **The pumps' new members ride with the host.** The gateway suite's cases write `status` and the counts on the embedded OpcServer's pumps, so the nodeset's `totalCount`, `rejectCount` and `reasonCode` and the contract's fields go in Phase 2's PR, where the suite first needs them; the emulator's `production` mode and `stops` list, which make them move on their own, are Phase 7. The reasons and codings tables, piece 3's, are built with the other tables in Phase 2, and the help topic, piece 6's, with the admin pages in 6a, since each is the shape of what sits beside it.
- **Piece 2 is two PRs and piece 6 two phases.** The host's write path from the stream is one PR and its rebuilds another, since the first is useful alone and the second is where the review's edge cases live (its #5 to #10). The web's machine page is useful before the dashboard, and the dashboard's live tiles need Phase 5.
- **The routes moved under the gateway's app page.** The spec's pages sit under `apps/gateways/<instance>/…` ([`app.routes.ts:106`](../../web/opc/site/app/app.routes.ts#L106)), where the templates' and groups' detail pages are, since `gateways/<slug>/…` is the browse tree ([`:32`](../../web/opc/site/app/app.routes.ts#L32)) and takes every segment for a connection; the spec's *Web* was changed to say so with this plan.
- **No Phase 0.** The ladders the reads and mutations join exist and the hub calls them ([`GatewayQL.cpp:35`](../../apps/OpcGateway/src/ql/GatewayQL.cpp#L35), [`HubQL.cpp:13`](../../apps/OpcHub/src/ql/HubQL.cpp#L13), [`:20`](../../apps/OpcHub/src/ql/HubQL.cpp#L20)), the add-on loader is merged (#302) and the group gate by guid is merged (#357); nothing outside the pieces is a prerequisite.

## Risks

- **Cites against a moving main.** The calendar's phases land in `Gateway::Connect`, the ladders and the gateway's CMake before Phase 2 starts, so each phase's PR re-reads the lines it leans on.
- **The calendar's slip.** Phase 2 cannot start until the calendar client merges; Phases 1 and 7 can start at once, and Phase 1 against the calendar library's branch if it has to.
- **Row volume.** Fifty machines at the minute write a million rows a fortnight: `ExecuteAwait` batches per `settle` tick, the unique index on machine and start serves the range reads, and a `by` that would exceed `readLimit` is refused; the suites run on sqlite, so Milestone I's figure for MySQL is a measurement to take, with retention the spec's *Later*.
- **The rebuild path's cost.** Every late record is a `Group::Read`; the heartbeat skip, the source offset and the `MinTimeInterval` warning are what keep it rare, and Phase 3's suite counts rebuilds on a plain shift to prove none slips through.
- **Clocks in tests.** The engine and the host take an `IClock`, so both suites move time by hand, and the gateway's shift cases are backfills that need no clock at all; a case that waited a minute of wall clock would be a test killed at the suite's timeout, so none does.
- **The hub.** `OeeSubscribe` runs in the hub's socket session unchanged and the mutations through its ladder; the hub's suite proves one of each.
- **The add-on's licence.** `xrange` is Highcharts Core, which the Stock licence covers; the Gantt product is not loaded. Without the add-on the pages are their figures and tables.
- **Spec drift.** A PR that changes behaviour changes [`spec.md`](spec.md) with it.
