# PLCs implementation plan - 2026-10-21

**Parked 2026-10-21** with the spec ([`spec.md`](spec.md), its first paragraph): the issues stay open under [#430], labelled `parked`, the three milestones below are closed, and the Open Protocol plan takes over the generic halves of phase 1 ([#433], the `kind` column) and phase 2b ([#435], the per-row server host, its trust anchor and own-certificate rule).

A plan for [`spec.md`](spec.md) (2026-10-21), whose fourteen open questions were ruled as recommended the same day and whose review's fifteen findings ([`plcs-spec-review.md`](../../../reviews/plcs-spec-review.md)) were applied the same day, here too; this plan's own review ([`plcs-plan-review.md`](../../../reviews/plcs-plan-review.md)), fourteen findings, was applied the same day, its first re-ruling the rights model to the spec's group-keyed fallback. It has the shape of the servers plan ([`../servers/plan.md`](../servers/plan.md)): prerequisites that are each useful alone, then the spec's pieces in dependency order, each phase a PR with its own tests, and three milestones that merge end to end. Status is tracked on GitHub: [#430] is the parent, each phase below names its issue, whose body is the plan's text at filing and is refreshed from here after a fold, and the milestones are [I](https://github.com/Jde-cpp/opc-hub/milestone/17), [II](https://github.com/Jde-cpp/opc-hub/milestone/18) and [III](https://github.com/Jde-cpp/opc-hub/milestone/19).

Line numbers cite opc-hub2 at `fc413ed1`, as the spec does; libplctag refs are v2.7.2. Refs re-anchored on 2026-10-23, the UA server library's move among them, cite branch `servers-1a-ua-server-library`.

Three things the spec's piece table does not say:

- **The server library lands first.** Every phase from 2b builds on `Jde.Opc.UAServer`, the servers plan's phase 1 ([#380](https://github.com/Jde-cpp/opc-hub/issues/380), [#381](https://github.com/Jde-cpp/opc-hub/issues/381)), and the hub's sessions on the in-process lookup its phase 2 adds ([#382](https://github.com/Jde-cpp/opc-hub/issues/382)). Phases 0, 1 and 2a touch none of it and can start now.
- **Piece 3 is two phases.** The listing decode and the address-space model are a library of their own, tested from byte buffers and json with no server running; the server and its value source come after, and the first is useful to the second's review before any thread exists.
- **The simulator is a prerequisite.** Every phase from 2b tests against libplctag's `ab_server`, so its fixture comes first, with the library, and proves the tool runs on both runners before a line of driver code is written. What it cannot do, the tag listing and the Identity object, are the plan's hardware dependencies (spec *Open questions* #14), and Phase 6 holds them.

## Risks

- **The library's threads.** Its callbacks run on its threads with its mutexes held, and a blocking API call there, or `plc_tag_lock`, deadlocks; the rule of the spec's *Values* holds: a callback posts and returns, `plc_tag_read` at timeout 0 is the only call made under the service lock, and creates, destroys and writes run on the row's strand. The shutdown log of lock hold times is the check.
- **Pending reads.** The server bounds no sampled read, so the host's `readTimeout` and the cancel callback are all that stands between a dead controller and a monitored item stuck at eight outstanding reads; the `--delay` test past `readTimeout` is the check.
- **No hardware before Phase 6.** 2a's decoder is proven against an encoder written from the same reading of the layout; a controller may list something the tool's author never met. The listing is also libplctag's own code path, which has decoded real controllers since 2.0, so the risk is in our model, not the bytes.
- **The rights lookup under the service lock.** Phase 3's `INodeAccess` runs in the value source's callbacks under the service lock and must stay a lookup, `Authorize::Rights` with the criteria overload, never `Gate`, the rule the servers spec's *Threading* states and the OpcServer met once.
- **Threading on Windows.** `UA_Server_*` from the row's strand relies on `UA_MULTITHREADING` at 100, which the superbuild does not pin ([`build/CMakeLists.txt:491`](../../build/CMakeLists.txt#L491)) and the servers plan flags as unverified on Windows ([`../servers/plan.md`](../servers/plan.md) *Risks*); 2b inherits that check.
- **The simulator's gaps.** `ab_server` answers neither the Identity object nor the listing, so `testConnection`'s identity and count and the listing itself are Phase 6's hand checks, and the suite proves the list path.
- **Windows.** libplctag's tier-one Windows build is MSVC, and the superbuild compiles it with clang on the VS runtime, as it does every dependency; its toolchain files are the thing to watch in 0.1, and the Windows suite is dispatch-only, so 0.2's spawn on Windows is run by hand once.
- **Ports.** `portBase + id` collides with a service on the box only by accident; the start-up error names the port and the key.
- **Spec drift.** A PR that changes behaviour changes `spec.md` with it, and the open questions' rulings are folded as they come.
