# Flows implementation plan - 2026-10-21

A plan for [`spec.md`](spec.md) (2026-10-21), whose open questions #1 to #5 and #13 were ruled as recommended the same day and #7 by 0.4's spike on 2026-11-12, #6 and #8 to #12 standing on their recommendations until ruled, and whose review's fifteen findings ([`flows-spec-review.md`](../../../reviews/flows-spec-review.md)) were applied the same day, as were its own review's fourteen ([`flows-plan-review.md`](../../../reviews/flows-plan-review.md)), the same day again. It has the shape of the PLCs plan ([`../plcs/plan.md`](../plcs/plan.md)): prerequisites that are each useful alone, then the spec's pieces in dependency order, each phase a PR with its own tests, and three milestones that merge end to end. Status is tracked on GitHub: [#444] is the parent, each phase below names its issue, whose body is the plan's text at filing and is refreshed from here after a fold, and the milestones are [I](https://github.com/Jde-cpp/opc-hub/milestone/20), [II](https://github.com/Jde-cpp/opc-hub/milestone/21) and [III](https://github.com/Jde-cpp/opc-hub/milestone/22).

Line numbers cite opc-hub2 at `fc413ed1`, as the spec does; open62541 refs are v1.5.9, quickjs-ng refs are v0.17.0, those added since 0.1 was built v0.18.0, its pin. Refs re-anchored on 2026-10-23, the UA server library's move among them, cite branch `servers-1a-ua-server-library`.

Four things the spec's piece table does not say:

- **The library lands without its Function node.** Phase 1 is the graph, the engine and every stock node under a manual clock, with no JavaScript in it, so its suite runs before quickjs-ng is in the superbuild; the Function node is a phase of its own after 0.1, since quickjs-ng is the only new dependency and the sandbox is the only code that needs it.
- **The trace is an interface from the start.** The engine's hooks call an `ITrace` from phase 1, which the library's suite implements in memory and the host implements over day files in phase 5, so the host of phase 2 runs with live counters alone and no read changes the engine when the files come.
- **Three external waits, none on the critical path.** The flow server waits on the servers plan's library ([#380], [#381]) and the Open Protocol plan's `kind` column and driver host ([#465], [#466]), which took over the parked PLCs plan's generic halves; the `calendar` source waits on the calendar plan's client ([#395]); the watch list's filter and strictest-wins merge on `opc in` wait on the clients plan's 6a ([#418]), the sampling, queue and discard parameters being there today. Every other phase builds on what is merged.
- **The web starts with a spike.** The canvas library is the one choice the spec leaves open with a cost behind it (*Open questions* #7), so 0.4 tries it on this workspace's Angular before phase 9 is sized on it.

Built 2026-11-12, where it differs from the text above:

- **The headers** are [`Message.h`](../../include/jde/flows/Message.h), [`Graph.h`](../../include/jde/flows/Graph.h), [`Node.h`](../../include/jde/flows/Node.h), [`Context.h`](../../include/jde/flows/Context.h), [`Trace.h`](../../include/jde/flows/Trace.h) and [`Flow.h`](../../include/jde/flows/Flow.h), in `Jde::Opc::Flows`. `Flow` is a handle over the engine, and runs once: a restart is another `Flow`.
- **`Start` makes the nodes and returns.** The host's `Source` and `Sink` are called on the caller's thread, and a refusal there leaves the flow stopped with `Fault`, the node and the message, and the node's status. The nodes' own `Start` runs on the strand after it returns, and one that throws stops the flow the same way. A `Stop` while the nodes are made wins, and `Start` answers false. `Stop` posts the teardown and takes a callback for its end, which a second `Stop` also gets behind that teardown. A `Flow` assigned over is stopped.
- **The queues are under a mutex**, so a source's `Emit` from any thread is bounded as a send is. What a source emits waits at the source's own queue, and is born when the strand takes it. A drop is counted and traced as it happens, and the node's status says `n dropped` once a drain, as it says `n uncaught` for what no catch took. A drain takes 1,000 messages a turn and posts the rest behind the strand's other work, so a timer or a `Post` from off the strand waits no longer than that.
- **A node holds a message by saying so.** `Receive` finishes the message when it returns unless the node called `Hold`, which `Done`, `Fail` or `Drop` ends later, on the strand, where `Post` brings a node back from any thread. What escapes a node's `Post` or timer is that node's error, counted, traced and in its status.
- **A timer is dispatched to the strand**, so one a clock runs on the strand runs there and then, and what it sends is through the flow before the clock moves on, its drain whole. That is how the suite advances its clock, and what phase 7's stream clock needs. The waits are intervals, never times compared, but a tumbling window's end.
- **`_id` is the run's start in seconds in its high half and a counter in its low**, from a `MessageIds` the host shares among its flows. `_time`, `sourceTime` and `serverTime` are ISO 8601 text.
- **A data change's payload** is `ToPayload`'s: `Value::ToJson`'s value with each `Long` object, at any depth, put back to its integer.
- **A graph is checked by making its nodes.** `Graph::Read` answers the graph or a `Fault`. A `name` of `""` is no name, as an editor writes one. A hosted node's props are its host's to check, in phase 3. A `function` node is refused until phase 4. A wire to a node that takes no input and a wire from a port the node lacks are faults too. A `link out` needs its `link in` in the same graph, until phase 3 has the other flows.
- **The props** each node reads:

  | Node | Props |
  | --- | --- |
  | `inject` | `message`, the message it sends |
  | `switch` | `property`, `checkall`, `rules` of `{ t, v, vt }` with Node-RED's `eq neq lt lte gt gte btwn cont regex true false null nnull empty nempty istype else`, `v2` and `v2t` for `btwn`, `case` for `regex` |
  | `change` | `rules` of `{ t: set, p, pt, to, tot }`, `{ t: delete, p, pt }` and `{ t: move, p, pt, to, tot }` |
  | `filter` | `property`, `band`, `percent`, `perTopic` |
  | `range` | `property`, `minIn`, `maxIn`, `minOut`, `maxOut`, `action` of `scale`, `clamp` or `wrap`, `round` |

  | `window` | `property`, `kind` of `tumbling` or `sliding`, `duration` or `count`, `perTopic` |
  | `join` | `mode` of `auto`, `array` or `object`, `count`, `timeout`, `key` |
  | `template` | `template`, `property`, `output` of `text` or `json` |
  | `debug` | `level`, `active` |
  | `catch` | `scope`, `uncaught` |
  | `status`, `complete` | `scope` |
  | `link in`, `link out` | `name` |

  A `vt`, `pt` or `tot` is `msg`, `flow` or `global`, and without one the value is the json itself. A duration is ISO 8601.
- **No rule coerces and none computes.** A `switch` compares numbers by value and never text with a number, and neither it nor `change` has an expression.
- **`template` is mustache's variables alone**: `{{name}}` escaped as mustache.js escapes, `{{{name}}}` and `{{&name}}` as they are, `{{flow.key}}` and `{{global.key}}`, and a comment. A section, a partial or a delimiter is a fault. A double is written as JavaScript's `String` writes it, `1450.5` and not `1.4505E3`, and a switch's `regex` reads a number the same way.
- **`delay` keeps the order the messages came in** and bounds what it holds at `queue`, in either mode.
- **A tumbling window by duration is the clock's**, each a multiple of the duration from its epoch, sent at its end when it holds a value. A sliding window is sent at each value. A message with a `reset` property empties every window.
- **A message a node makes has the last message that went into it as its `_parent`**: a window's, a join's and a trigger's second.
- **What a catch takes is a clone**, under a new `_id` with the failed message as its `_parent`, and an `error` the message came with is kept as `_error`. A catch for the uncaught is asked last. What escapes a timer's callback is its node's error with no message.

## Risks

- **Everything on the strand.** `OnRecords` runs on the historian's path, a `WriteAwait` or `ClientHttpAwait` resumes on whatever thread completes it, and a timer on the executor's; every one must re-post to the flow's strand before it touches a node, as `DurationTimer` takes an executor to resume on ([`Timer.h:24`](../../include/jde/fwk/co/Timer.h#L24)). The debug assertion on every entry and the two-flow global-store test are the checks.
- **The interrupt handler is polled.** quickjs-ng calls it between bytecodes, so a body inside one long native call, a `JSON.parse` of a huge string, is not interrupted until it returns, where a regex is, the engine polling the handler as it backtracks ([`libregexp.c:2800`](https://github.com/quickjs-ng/quickjs/blob/v0.17.0/libregexp.c#L2800)); the memory limit and the stack limit bound what such a call can do, and the help names the timeout as a guard, not a cap.
- **Trace volume.** The spec's arithmetic puts a busy flow at gigabytes a day at `hops`; the roll's walk across every flow's days must stay cheap on a directory tree of thousands of days, so it walks newest first and stops at the first day it keeps.
- **The canvas library.** 0.4 settled the fit. What is left is that its managed state is at its first version, which records neither rotation nor a wire's waypoints, neither of which the editor has. Phase 9 pins the version walked, and the records are the editor's own shape, so another library would cost the canvas component and not the page.
- **The bundle.** Blockly is more than a megabyte with its generator and the canvas library 399 kB (0.4); each loads when its tab is shown, never with `main`, which the initial-bundle budget checks, and not with the route's chunk, which every tab preloads ([`reviews-issue/lazy-routes.md`](../../../reviews-issue/lazy-routes.md) has the three ways a page leaks into `main`).
- **At-least-once sinks.** A crash between a sink's firing and the mark's write fires the sink again on resume; `_id` is stable per record so a webhook can dedupe, and a PLC write is a setpoint, idempotent by nature; the help says so.
- **The flow server waits on two plans.** Phase 8 links the servers library and the Open Protocol plan's row and host; until both merge, every other phase ships with `variable` refused at deploy, and the demo's derived mean waits with it.
- **Windows.** quickjs-ng's CI covers clang and clang-cl, and the superbuild compiles it with clang on the VS runtime as it does every dependency; 0.1's Windows run of `win2025-deps` is the check, and the suite is dispatch-only there; its executor threads take the image's 1 MB stack, under which `function.stack` must sit, which the spec's default does.
- **The 450 s bound.** A replay in the gateway suite reads real records through a real historian; the cases replay minutes, and the days-long cases live in the library under the manual clock.
- **Spec drift.** A PR that changes behaviour changes `spec.md` with it, and the open questions' rulings are folded as they come.
