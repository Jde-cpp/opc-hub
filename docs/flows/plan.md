# Flows implementation plan - 2026-10-21

A plan for [`spec.md`](spec.md) (2026-10-21), whose open questions #1 to #5 and #13 were ruled as recommended the same day, #6 to #12 standing on their recommendations until ruled, and whose review's fifteen findings ([`flows-spec-review.md`](../../../reviews/flows-spec-review.md)) were applied the same day, as were its own review's fourteen ([`flows-plan-review.md`](../../../reviews/flows-plan-review.md)), the same day again. It has the shape of the PLCs plan ([`../plcs/plan.md`](../plcs/plan.md)): prerequisites that are each useful alone, then the spec's pieces in dependency order, each phase a PR with its own tests, and three milestones that merge end to end. Status is tracked on GitHub: [#444] is the parent, each phase below names its issue, whose body is the plan's text at filing and is refreshed from here after a fold, and the milestones are [I](https://github.com/Jde-cpp/opc-hub/milestone/20), [II](https://github.com/Jde-cpp/opc-hub/milestone/21) and [III](https://github.com/Jde-cpp/opc-hub/milestone/22).

Line numbers cite opc-hub2 at `fc413ed1`, as the spec does; open62541 refs are v1.5.9, quickjs-ng refs are v0.17.0. Refs re-anchored on 2026-10-23, the UA server library's move among them, cite branch `servers-1a-ua-server-library`.

Four things the spec's piece table does not say:

- **The library lands without its Function node.** Phase 1 is the graph, the engine and every stock node under a manual clock, with no JavaScript in it, so its suite runs before quickjs-ng is in the superbuild; the Function node is a phase of its own after 0.1, since quickjs-ng is the only new dependency and the sandbox is the only code that needs it.
- **The trace is an interface from the start.** The engine's hooks call an `ITrace` from phase 1, which the library's suite implements in memory and the host implements over day files in phase 5, so the host of phase 2 runs with live counters alone and no read changes the engine when the files come.
- **Three external waits, none on the critical path.** The flow server waits on the servers plan's library ([#380], [#381]) and the Open Protocol plan's `kind` column and driver host ([#465], [#466]), which took over the parked PLCs plan's generic halves; the `calendar` source waits on the calendar plan's client ([#395]); the watch list's filter and strictest-wins merge on `opc in` wait on the clients plan's 6a ([#418]), the sampling, queue and discard parameters being there today. Every other phase builds on what is merged.
- **The web starts with a spike.** The canvas library is the one choice the spec leaves open with a cost behind it (*Open questions* #7), so 0.4 tries it on this workspace's Angular before phase 9 is sized on it.

## Risks

- **Everything on the strand.** `OnRecords` runs on the historian's path, a `WriteAwait` or `ClientHttpAwait` resumes on whatever thread completes it, and a timer on the executor's; every one must re-post to the flow's strand before it touches a node, as `DurationTimer` takes an executor to resume on ([`Timer.h:24`](../../include/jde/fwk/co/Timer.h#L24)). The debug assertion on every entry and the two-flow global-store test are the checks.
- **The interrupt handler is polled.** quickjs-ng calls it between bytecodes, so a body inside one long native call, a `JSON.parse` of a huge string, is not interrupted until it returns, where a regex is, the engine polling the handler as it backtracks ([`libregexp.c:2800`](https://github.com/quickjs-ng/quickjs/blob/v0.17.0/libregexp.c#L2800)); the memory limit and the stack limit bound what such a call can do, and the help names the timeout as a guard, not a cap.
- **Trace volume.** The spec's arithmetic puts a busy flow at gigabytes a day at `hops`; the roll's walk across every flow's days must stay cheap on a directory tree of thousands of days, so it walks newest first and stops at the first day it keeps.
- **The canvas library's fit.** `@foblex/flow` is sized on 0.4's spike against Angular 22; a failed spike swaps the library before phase 9 and changes nothing else.
- **The bundle.** Blockly is more than a megabyte with its generator and the canvas library a few hundred kilobytes; both load with their pages and never with `main`, which the initial-bundle budget checks ([`reviews-issue/lazy-routes.md`](../../../reviews-issue/lazy-routes.md) has the three ways a page leaks into `main`).
- **At-least-once sinks.** A crash between a sink's firing and the mark's write fires the sink again on resume; `_id` is stable per record so a webhook can dedupe, and a PLC write is a setpoint, idempotent by nature; the help says so.
- **The flow server waits on two plans.** Phase 8 links the servers library and the Open Protocol plan's row and host; until both merge, every other phase ships with `variable` refused at deploy, and the demo's derived mean waits with it.
- **Windows.** quickjs-ng's CI covers clang and clang-cl, and the superbuild compiles it with clang on the VS runtime as it does every dependency; 0.1's Windows run of `win2025-deps` is the check, and the suite is dispatch-only there; its executor threads take the image's 1 MB stack, under which `function.stack` must sit, which the spec's default does.
- **The 300 s bound.** A replay in the gateway suite reads real records through a real historian; the cases replay minutes, and the days-long cases live in the library under the manual clock.
- **Spec drift.** A PR that changes behaviour changes `spec.md` with it, and the open questions' rulings are folded as they come.
