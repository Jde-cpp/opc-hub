# Clients spec

2026-10-20, its open questions ruled the same day, and the review's 21 findings ([`clients-spec-review.md`](../../../reviews/clients-spec-review.md)) ruled and folded the same day; its plan is [`plan.md`](plan.md) (2026-10-20), whose review folded twelve of its findings here 2026-10-21 and whose issues are filed under [#411](https://github.com/Jde-cpp/opc-hub/issues/411). The client-side counterpart of the servers spec ([`../servers/spec.md`](../servers/spec.md)), which made the gateway a UA server: this one takes the gateway as a UA client, and the web pages over it, against what a full OPC UA client gives its user. Nothing here is built.

## Overview

The gateway is the product's OPC UA client. It holds one open62541 client per connection and credential (`apps/OpcGateway/README.md:3`), and the web app reaches a server through it: GraphQL for browse, read and write, the `/opc` socket for subscriptions, and the historian behind both. A connection is a row: a url, a certificate URI, a default browse namespace, a slug ([`ServerCnnctn.h:18`](../../apps/OpcGateway/src/types/ServerCnnctn.h#L18)). A session's credential is the user's, an issued hub token, a user name and password on that server, or the gateway's own certificate ([`OpcServerSession.h:12`](../../apps/OpcGateway/src/auth/OpcServerSession.h#L12)), so the server enforces what the user may read, write and subscribe, and the gateway gates only its own tables, `search`, the sessions list ([`opcGateway-meta.jsonnet:84`](../../apps/OpcGateway/config/opcGateway-meta.jsonnet#L84)) and the historian's groups, each by its access row ([`HistHost.h:47`](../../apps/OpcGateway/src/hist/HistHost.h#L47)).

The measure is the general-purpose OPC UA client an integrator commissions a server with. Its base is discovery, a connection dialog over every endpoint a server offers, certificate management, an address-space browser from Root, an attributes window and a references window; over that, a live data view, a live trend, an event view with alarms and conditions, a history trend, a method call dialog, a server diagnostics view, a performance view, a CSV data logger, an image viewer, a DI view, a GDS push view, and PubSub, FX and NodeSet-export views. Against that, the gateway has the browse, the read, the write, one page's subscriptions, Part 11 history in every mode with edits, enums by name, and a search, and lacks the rest. The *Gaps* table says what, feature by feature, with where today's behaviour lives; *Design* says how each gap closes; *Pieces* sizes them.

Some of what the gateway has, such a client does not: a per-connection name index behind a search ([`NodeIndex.h:11`](../../apps/OpcGateway/src/NodeIndex.h#L11)), since UA has no search service; the historian, its trend and its edits ([`libs/historian/docs/spec.md`](../../libs/historian/docs/spec.md)); a hub session carried to the server as an issued token ([`OpcServerSession.h:12`](../../apps/OpcGateway/src/auth/OpcServerSession.h#L12)); subscriptions parked through a connection loss and restored on the reconnect ([`UAClient.cpp:1088`](../../apps/OpcGateway/src/UAClient.cpp#L1088)); a certificate issued per connection ([`Opc.Gateway.jsonnet:34`](../../apps/OpcGateway/config/Opc.Gateway.jsonnet#L34)); a host name whose first address takes no connection tried at its next ([`UAClient.cpp:802`](../../apps/OpcGateway/src/UAClient.cpp#L802)); and a failed connect explained in terms of the endpoints the server offers ([`UAClient.cpp:560`](../../apps/OpcGateway/src/UAClient.cpp#L560)). None of that moves.

Line numbers cite opc-hub2 at `fc413ed1`. Refs re-anchored on 2026-10-23, the UA server library's move among them, cite branch `servers-1a-ua-server-library`. open62541 refs are v1.5.9, the version the build links; the web refs are the sources under `web/opc/control/src`, which the workspace links to.

## Design

**Discovery.** `discover( url, servers: true )` runs FindServers at `url`, a Local Discovery Server at `opc.tcp://host:4840` or any server, which answers with itself ([`client.h:288`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L288)), and answers each server's applicationUri, applicationName, applicationType and discoveryUrls; `discover( url )` runs GetEndpoints at a server url ([`client.h:262`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L262)) and answers each endpoint's url, policy, mode, securityLevel, its token policies by type and policy, and the server's certificate, decoded by *Trust*'s reader: subject, issuer, validity, SAN URI, thumbprint. Both run on a throwaway None-policy client built as the connect diagnostics build theirs ([`UAClient.cpp:488`](../../apps/OpcGateway/src/UAClient.cpp#L488)), both are synchronous services and go to the blocking pool that [#353](https://github.com/Jde-cpp/opc-hub/issues/353) moves the connect onto, and both are a system mutation, as `testConnection` is and for its reason ([`TestConnectionQLAwait.h:6`](../../apps/OpcGateway/src/ql/TestConnectionQLAwait.h#L6)): the gateway connects to a url of the caller's choosing. The right is `testConnection`'s, Update on `gateway/serverConnections` ([`client-detail.ts:90`](../../web/opc/control/src/lib/pages/gateway-detail/client-detail/client-detail.ts#L90)). The connection page gets a Discover button beside Test Connection: the servers found, the endpoints of the one picked, and a pick fills the url, the certificate URI with the server's applicationUri, and the mode and policy of *Connection settings*. FindServersOnNetwork, the mDNS listing, is not in this build: open62541 is compiled without multicast discovery ([`CMakeLists.txt:165`](https://github.com/open62541/open62541/blob/v1.5.9/CMakeLists.txt#L165), [`:167`](https://github.com/open62541/open62541/blob/v1.5.9/CMakeLists.txt#L167)), and *Open questions* #7 leaves it there.

**Connection settings.** `server_connections` ([`opcGateway-meta.jsonnet:22`](../../apps/OpcGateway/config/opcGateway-meta.jsonnet#L22)) grows nullable columns, null meaning today's rule: `security_mode`, None, Sign or SignAndEncrypt; `security_policy`, a policy uri; `session_timeout`, `request_timeout`, `ping_interval` and `ttl`, durations; `locale`, a list of locale ids. `Configuration()` ([`UAClient.cpp:351`](../../apps/OpcGateway/src/UAClient.cpp#L351)) pins `config->securityMode` ([`client.h:671`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L671)) and `securityPolicyUri` ([`:675`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L675)) from the row where it names them, and keeps the floor as it is where it does not: a certificate URI means Sign & Encrypt, none means None. Sign needs the connection's certificate as Sign & Encrypt does, so a row asking for Sign without a certificate URI is refused at save. A Sign row sends a secret, a password or an issued token, only under a token policy that encrypts it, or under `/gateway/allowPlaintextPassword`, the rule a None row is under ([`UAClient.cpp:424`](../../apps/OpcGateway/src/UAClient.cpp#L424)): a Sign channel signs, it does not hide. The deprecated policies, Basic128Rsa15 and Basic256, exist in 1.5.9 ([`securitypolicy_default.h:26`](https://github.com/open62541/open62541/blob/v1.5.9/plugins/include/open62541/plugin/securitypolicy_default.h#L26), [`:32`](https://github.com/open62541/open62541/blob/v1.5.9/plugins/include/open62541/plugin/securitypolicy_default.h#L32)) and stay out of the carried set ([`UAClient.cpp:338`](../../apps/OpcGateway/src/UAClient.cpp#L338)), as today, which *Open questions* #2 keeps; the ECC policies ([`:58`](https://github.com/open62541/open62541/blob/v1.5.9/plugins/include/open62541/plugin/securitypolicy_default.h#L58)) need an ECC certificate and are later. `Create()` ([`UAClient.cpp:712`](../../apps/OpcGateway/src/UAClient.cpp#L712)) sets `requestedSessionTimeout` ([`client.h:649`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L649)), `timeout` ([`:613`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L613)) and `sessionLocaleIds` ([`:635`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L635)) from the row, so a server with several locales answers DisplayName and Description in the site's. The keep-alive ([`AsyncRequest.cpp:42`](../../apps/OpcGateway/src/async/AsyncRequest.cpp#L42)) and the idle TTL take the row's values over `/gateway/pingInterval` and `ttl` ([`AsyncRequest.h:11`](../../apps/OpcGateway/src/async/AsyncRequest.h#L11)), and a row that sets `session_timeout` without `ping_interval` gets a ping at half of it, so the lapse the log warns of ([`AsyncRequest.cpp:52`](../../apps/OpcGateway/src/async/AsyncRequest.cpp#L52)) cannot be configured by accident. Half of the requested value: a server may revise the timeout lower in its CreateSession response, and open62541 exposes no revised value, its connection attributes being the server description, the policy and the mode ([`client.h:484`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L484)), so against a server that revises it under twice the ping the keep-alive's lapse warning stands. `ConnectionEdited` already rebuilds every client of an edited row ([`UAClient.cpp:201`](../../apps/OpcGateway/src/UAClient.cpp#L201)). The two save rules run on insert and on update, over the merged row, on every write, before the gateway's startup is done and while the AppServer is out of reach as well, since only the provider row waits for those, and the cross-column half of the second, a secured mode or policy without the URI and a mode and policy that contradict, is a trigger per dialect as well ([`mysql/gateway_server_connection_insert.sql:19`](../../apps/OpcGateway/config/sql/mysql/gateway_server_connection_insert.sql#L19), [`sqlite/gateway_server_connection_update.sql:16`](../../apps/OpcGateway/config/sql/sqlite/gateway_server_connection_update.sql#L16), [`sqlServer/gateway_server_connection_insert.sql:10`](../../apps/OpcGateway/config/sql/sqlServer/gateway_server_connection_insert.sql#L10)), so two updates that each passed against the saved row cannot together store a row the rule refuses ([#520](https://github.com/Jde-cpp/opc-hub/issues/520)): the race's loser gets the trigger's message as a 400, as a stored procedure's own refusal comes back; a statement that leaves the three columns as they are is not checked, so the insert proc's `is_default` reset passes a row stored before the rule; the engine saves an empty string as null in a nullable text column, so the triggers read an unset column with `is null` alone, since SQL Server's `=` pads and `''` would match `' '` too; `testConnection( opc, url, certificateUri )` ([`TestConnectionQLAwait.h:6`](../../apps/OpcGateway/src/ql/TestConnectionQLAwait.h#L6)) takes the new columns as optional arguments, null meaning the gateway's value as the row's null does, and applies them too, so the page tests the connection it is about to save. The Connection tab shows the negotiated policy and mode as it does ([`server-properties.ts:40`](../../web/opc/control/src/lib/pages/gateway-detail/client-detail/server-properties/server-properties.ts#L40)), and the help's *Security* section (`assets/help/gateways.md:86`) says what the new columns do.

**Trust.** The verifier ([`ServerTrust.cpp:32`](../../libs/opc/shared/src/ServerTrust.cpp#L32)) writes the certificate it rejects to `/gateway/rejectedCertDir`, default `ssl/servers/rejected` beside `ssl/servers`, as `<thumbprint>.der`, the SHA-1 of the DER, which is the thumbprint a client shows and the secure channel names, once per certificate, the servers spec's rule for the endpoint's client certificates turned round; the reader is `Crypto::Certificate` ([`CryptoSettings.h:33`](../../include/jde/fwk/crypto/CryptoSettings.h#L33)), which gains that thumbprint and a `NotBefore` beside its SHA-256 `Fingerprint` ([`:54`](../../include/jde/fwk/crypto/CryptoSettings.h#L54)) and `Expiration`; `EnsureDirs` creates it ([`ServerTrust.cpp:101`](../../libs/opc/shared/src/ServerTrust.cpp#L101)). The verifier knows the url alone ([`ServerTrust.cpp:44`](../../libs/opc/shared/src/ServerTrust.cpp#L44)), so the last rejection's thumbprint is recorded per slug as the connect errors are ([`UAClient.cpp:52`](../../apps/OpcGateway/src/UAClient.cpp#L52)), and `serverConnections{ rejectedCertificate{ subject issuer notBefore notAfter uri thumbprint } }` reads that file, and the Connection tab shows it under the *Not connected* reason with a Trust button: `trustServer( opc, thumbprint )`, a system mutation under Administer on `gateway/serverConnections`, moves the file into `ssl/servers` under the gateway's own data folder, the rejected directory's sibling, which must be among `trustedCertDirs` ([`Opc.Gateway.jsonnet:53`](../../apps/OpcGateway/config/Opc.Gateway.jsonnet#L53)) for the move to mean anything, the mutation refused with that message when it is not, and never the list's first entry, which in the test suite is the AppServer's enrollment anchors ([`Opc.Tests.jsonnet:16`](../../apps/OpcGateway/tests/config/Opc.Tests.jsonnet#L16)), and reconnects the slug through `ConnectionEdited`, since the list is loaded per connect ([`ServerTrust.h:13`](../../include/jde/opc/ServerTrust.h#L13)). The same tab shows the certificate the gateway presents for the connection, `PresentedCertificate` ([`UAClient.cpp:439`](../../apps/OpcGateway/src/UAClient.cpp#L439)): path, subject, validity and URI, with the PEM itself as `serverConnections{ clientCertificate{ pem } }`, under the table's Read as the rest of the row is and offered by the page as a download, no new route, so an operator carries it to a third-party server's trust list, which the help describes by path today (`assets/help/gateways.md:107`). The store checks the chain and the validity dates ([`TrustStore.cpp:66`](../../libs/fwk/src/crypto/TrustStore.cpp#L66)) and nothing else; open62541's client checks only its own certificate's URI ([`ua_client_connect.c:2104`](https://github.com/open62541/open62541/blob/v1.5.9/src/client/ua_client_connect.c#L2104)). A server certificate whose SAN URI differs from the endpoint's applicationUri, or whose SAN names neither the url's host nor its address, is logged at Warning and not refused (*Open questions* #14).

## Open questions

All fourteen ruled 2026-10-20: #2 against its recommendation, #10 as recommended with its machinery placed in the servers spec's library, the rest as recommended. The review's 21 findings ([`clients-spec-review.md`](../../../reviews/clients-spec-review.md)) were ruled fix-as-recommended and folded the same day; its #9 and #10 restate #9 and #1 below.

1. **Scope.** This spec reads "the clients" as the gateway's UA client and the web pages over it, with the OpcServer changed only where the tests and the rights need it, the Execute mapping of #9, a test method, a test event source and the condition object of #10, and the emulator, which is no UA client, untouched. Recommended: that reading. Ruled 2026-10-20: as recommended; restated the same day to admit the OpcServer changes (review #10).
2. **Legacy security policies.** Basic128Rsa15 and Basic256 are deprecated and the gateway refuses a server that offers nothing else ([`UAClient.cpp:372`](../../apps/OpcGateway/src/UAClient.cpp#L372)), which is older PLC firmware. Recommended: an opt-in flag on the row, off by default, warned at every connect, so a site takes the weaker policy knowingly and the default stays as it is. The alternative, never, keeps those PLCs out of the product. Ruled 2026-10-20: not now - the deprecated policies stay uncarried and no flag is added; a site whose firmware offers nothing else is the case to revisit.
3. **Sign alone.** Recommended: allowed when the row names it; the default with a certificate URI stays Sign & Encrypt. A site that wants its traffic readable on the wire for a protocol analyser, with the channel still authenticated, is the case. Ruled 2026-10-20: as recommended.
4. **Shared items.** One item per node per client, strictest wins. Recommended. The alternative, an item per listener, doubles the server's items for the common case of two tabs on one node and makes the collector's own-client rule ([`OpcServerSession.h:41`](../../apps/OpcGateway/src/auth/OpcServerSession.h#L41)) the norm. Ruled 2026-10-20: as recommended.
5. **Where a structure decodes.** The gateway, against the client's registered types, so the history, the historian's records and every client of the QL see fields. Recommended. The alternative, shipping the DataTypeDefinition to the web and decoding there, decodes once per client and leaves the gateway's own readers, the historian included, with bytes. Ruled 2026-10-20: as recommended.
6. **Reverse connect.** Later. Recommended: open62541 has it ([`client.h:185`](https://github.com/open62541/open62541/blob/v1.5.9/include/open62541/client.h#L185)), but a connection becomes a listen rather than a dial, which changes `ConnectAwait`'s life cycle ([`ConnectAwait.cpp:125`](../../apps/OpcGateway/src/async/ConnectAwait.cpp#L125)) and is a piece of its own once a device behind a firewall needs it; none in the demo does. Ruled 2026-10-20: as recommended.
7. **mDNS discovery.** Later. Recommended: FindServersOnNetwork needs open62541 built with multicast discovery, Avahi on Linux and mdnsd on Windows, a dependency on each platform for a listing the LDS form of *Discovery* gives without it. Ruled 2026-10-20: as recommended.
8. **Trust from the web.** `trustServer` under Administer. Recommended: trusting a server is the one step that blocks every first connection to a third-party server, and it is a decision an admin makes from the page that shows the certificate. The alternative, files alone, is what the servers spec keeps for the endpoint's client list, where the admin is on the server's side anyway. Ruled 2026-10-20: as recommended.
9. **The method right on the OpcServer.** `OpcAuthorize` maps Update to UserExecutable, so a user who may write a node's values may call its methods. Recommended. The alternative, Administer, makes every call an admin's. Ruled 2026-10-20: as recommended; revisited the same day (review #9): the vocabulary already keeps `Execute` for methods ([`usings.h:32`](../../include/jde/access/usings.h#L32)) and the OpcServer denies every call today, so `GetUserExecutable` consults Execute, Update implying nothing.
10. **The conditions' test source.** A hand-built AlarmConditionType object on the OpcServer, driven by the emulator, with Acknowledge and Confirm as methods. Recommended: without it the Alarms view ships untested against anything. The alternative is to build the view against a third-party server by hand and file the test as a gap. Ruled 2026-10-20: as recommended, with the machinery placed: the condition object, its events and its Acknowledge, Confirm, AddComment and ConditionRefresh methods go in the shared server library the servers spec creates ([`../servers/spec.md`](../servers/spec.md), *The server library*), so both hosts can raise conditions; the OpcServer hosts the test source and the demo's alarms, declared in its nodeset, driven by the emulator for the demo and by the test itself in the suite; the gateway's endpoint raising conditions of its own, a connection lost, a group's values dropped, is a later piece of the servers spec, noted under its *Later*.
11. **LocalizedText.** Read as text, written as text or `{text, locale}`, the locale chosen by the session's locale ids. Recommended: the shape every reader has today stays, and the locale a site wants comes from the session. The alternative, `{text, locale}` on every read, changes a shape the web, the socket and the historian's clients parse. Ruled 2026-10-20: as recommended.
12. **`discover` as a mutation.** Recommended, for `testConnection`'s reason: a GET must not make the gateway connect to a url of the caller's choosing. Ruled 2026-10-20: as recommended.
13. **Watch list persistence.** As the saved table views are, per user. Recommended. A table, for lists shared between users, is later if asked for. Ruled 2026-10-20: as recommended.
14. **The server certificate's URI and host.** A warning in the log, not a refusal, when the certificate's SAN URI differs from the endpoint's applicationUri or its SAN names neither the url's host nor its address. Recommended: a self-signed PLC certificate often names neither, and the trust list is the gate. Ruled 2026-10-20: as recommended.
